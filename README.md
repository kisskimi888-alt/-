# 生鲜采购审单台

从四张历史 Excel 生成未来七天的品类采购参考，再对第一天的单品订单做供货检查、重排、确认和导出。项目包内含四张原始案例附件。

## 1. 启动网页

推荐用 Python 3.12。解压后，用终端进入有 `app.py` 的文件夹。

```bash
python -m venv .venv
```

Windows PowerShell 运行下面两行。

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m streamlit run app.py
```

macOS 或 Linux 运行下面两行。

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

浏览器打开终端显示的本地地址。在「数据与生成」选择「历史案例」，先点「核查数据」，再点「生成计划」。保留默认截止日 2023-06-30 即可生成 7 月 1 日的初始订单。历史大表读取和第一次预测会花一些时间。

## 2. 代码怎么读

建议先按下面的顺序看业务代码，最后看网页。每个文件开头都标了段落。

| 段落 | 文件 | 打开后先看 | 这段负责的事情 |
|---|---|---|---|
| 1 | `inputs.py` | `check_inputs()`、`daily_history()` | 检查四表表头、重复键和跨表关联，按截止日汇总交易 |
| 2 | `forecast.py` | `origin_features()`、`forecast_week()` | 用分品类树预测未来七天，按历史误差建立低、中、高需求 |
| 3 | `orders.py` | `validate_draft()`、`solve_order()`、`explain_limits()` | 检查现填数量，或把供应与业务约束交给求解器 |
| 4 | `planning.py` | `generate_plan()` | 把七天预测变成品类参考，再把第一天变成初始单品订单 |
| 5 | `storage.py` | `OrderStore.confirm()`、`order_xlsx()` | 确认指定草稿版本，生成独立快照，从快照导出三页 Excel |
| 6 | `app.py` | 四个页面区块 | 连接核查、生成、即时检查、重排、确认和下载 |
| 验收 | `tests/` | 测试名称和断言 | 核对原始附件、换表、三种审单结果、网页组件和导出版本 |

### 第 1 段｜先把数据接对

`check_inputs()` 按事先约定的工作表和列名读四张 Excel。比如销售流水只有编码，要用商品表找出名字和品类，再用「日期 + 单品编码」匹配批发价。找不到同日成本就明确报错，因为猜一个成本会直接影响收益和订单。

`daily_history()` 先按用户选的日期截断历史，再做两种汇总。正向成交量用于预测销售量和计算按成交量加权的历史价格。净销量字段保留销售和退货相抵的口径。某天无交易，预测训练把它视为缺失记录。最近七天有正向成交且净销量为正的单品进入候选。

### 第 2 段｜同一天出发，预测未来七天

`origin_features()` 给模型看的有过去第 1、7、14、28 天的销量，过去 7 天和 28 天的均值，以及预测目标那天是星期几、几月份。

`forecast_week()` 每个品类为七个步长分别训练树模型。假设今天是 6 月 30 日，预测 7 月 7 日时也只能使用到 6 月 30 日的数据。训练时同样检查标签日期，也就是用于做标准答案的那天是否早于训练截止日。月初固定训练窗口，七月案例用四月完整周的样本外残差校准。残差就是「实际 − 预测」，取 20%、50%、80% 分位数，分别加到点预测上，得到三个情景，权重 25%、50%、25%。

### 第 3 段｜同一份草稿，两种操作

**检查**是拿填写量算一次。订 10 kg、最多供 8 kg、损耗率 10%，就显示填了 10 kg、供货上限 8 kg、超出 2 kg，按供货条件可售 7.2 kg。如果预测需求是 6 kg，预计销量就是 6 kg。检查更新金额、预计销量和覆盖率，草稿保留填写的 10 kg，方便用户处理问题。

**重排**是让优化器在新条件下重新寻找订货组合。单品是否采购由一个 0/1 变量控制。选中后至少订 2.5 kg，供货上限直接约束数量，锁定则固定数量。还要在 27–33 个品种之间，并满足每个品类的覆盖门槛。优化目标是加权预计收入减采购成本。为保证网页、检查和导出的数量一致，求解器以整数克决定订货量，页面显示三位小数的公斤数。

`explain_limits()` 先检查锁定量与供货量是否冲突，再计算单个品类把可用供应都用上时的乐观覆盖上限。能算出确定缺口时，直接显示差多少。约束组合无解、求解超时、已有可用方案但最优性未确认，分别显示。

### 第 4 段｜把未来七天接到首日订单

`generate_plan()` 一次算完两份结果。七天品类计划先为每个品类、每一天试算不同采购量。需求达到一个情景的上限后，多订货只对更高的情景有价值，折线拐点就来自三种需求。固定价下把各拐点相邻的整数克都算一下，取贡献最大的数量。

首日订单只取第一天的需求。假如花菜预计需求是 30 kg，西兰花占近期花菜销量 80%，就给西兰花分到 24 kg 的该情景需求。三个情景都这样分，再把单品各自的成本、售价和损耗交给求解器。改单和重排共用这次计划已经存好的情景和参考需求。后续日期的参考采购量仍从原七天计划读取。

### 第 5 段｜确认后按订单号下载

每一次实质改动都保存一版新草稿。确认时从数据库取对应版本，再跑同一个检查函数，合格后生成一个独立订单。数据库用事务保证这几步一起完成。重复确认同一个草稿版本会返回同一个单号。

Excel 包含「采购明细」「订单信息」「修改记录」。按订单号读取确认快照即可导出。用户从确认单创建新草稿时，会保留来源单号和修改沿革。订单数据默认保存在本地 `data/state/orders.sqlite3`，可用环境变量 `ORDER_DESK_DB` 指定其他路径。

### 第 6 段｜网页把动作串起来

上传并核查 → 生成计划 → 修改草稿 → 检查，或查看并应用重排预览 → 确认 → 从已确认订单下载。预览绑定发起时的草稿版本，修改数量或供货以后会清掉旧预览。

## 3. 用原始案例走一遍审单

三个演示分别从刚生成的初始订单开始。重新点「生成计划」即可得到新草稿。

| 要演示什么 | 在审单表里怎么操作 | 预期看到什么 |
|---|---|---|
| 改完仍可用 | 把西兰花的订货量从 26.722 kg 改为 26.000 kg | 填写量和预计采购金额降低，草稿通过检查 |
| 需要重新分配 | 给西峡花菇(1) 填供货上限 5.571 kg，原订货量为 6.571 kg。点「按新条件重排」 | 草稿先报超供货。预览中西峡花菇降至 5.571 kg，虫草花、金针菇等调整。应用后才更新实际草稿 |
| 怎么分也不够 | 给西兰花填供货上限 0，再点「按新条件重排」 | 花菜类门槛约 27.23 kg，剩余候选最多覆盖 7.14 kg，仍差 20.09 kg |
| 保留确认版本 | 确认并下载第一版，从它创建新草稿，改单并确认新版 | 已确认订单页可以按单号分别下载，两版修改记录可追溯 |

## 4. 在 Jupyter 里单独运行

把 Notebook 放在与 `app.py` 同一个文件夹，使用已经安装依赖的 Python 内核。下面四个小段可以分别放入四个单元格。

```python
from inputs import check_inputs, read_demo
batch = check_inputs(read_demo("data/demo"))
batch.rows
```

```python
from planning import generate_plan
plan = generate_plan(batch, "2023-06-30")
len(plan["week"]), len(plan["candidates"]), plan["initial_status"]
```

```python
from orders import new_draft, validate_draft
draft = new_draft(plan)
audit = validate_draft(plan, draft)
audit["selected"], audit["quantity_g"] / 1000, round(audit["contribution"], 2)
```

```python
from orders import solve_order
draft["items"]["102900005116714"]["cap_g"] = 0  # 西兰花缺货
solve_order(plan, draft)
```

## 5. 复跑与核对

使用与网页相同的 Python 环境，在项目目录运行。

```bash
python planning.py --input-dir data/demo --as-of 2023-06-30
python -m unittest discover -s tests -v
```

本版原始案例生成 42 条品类计划、49 个首日候选，初始订单包含 33 个单品、合计 425.075 kg、预计采购金额 1,810.32 元、模拟贡献 615.27 元。

工作区可复用的旧 Notebook 是单日预测版本。本项目依照先前确定的七天固定起点方法重建了预测与校准，当前结果使用随包交付的实现。前一次三问版的约 417.81 kg 和 553.18 元是另一份实现的对照值。两次结果的差异还无法逐行归因。

数据来源为 2023 年全国大学生数学建模竞赛 C 题。参考零售价和进货价来自历史成交记录。覆盖和贡献基于历史销量代理、损耗假设与模拟供货，库存、真实供应商报价和替代购买行为需要门店另行提供。
